# Getting started

Praxis 1.0.0 contains all 28 runtime packages as a local Codex plugin. Install
it from the repository marketplace:

```bash
# Run from the dotfiles repository root.
codex plugin marketplace add .
codex plugin add praxis@praxis-personal
```

Read the [landing page](../../README.md) and [integration contracts](../reference/integrations.md)
for the separate Pi and OpenCode host boundaries.

## Make a first request

Use ordinary language. Name the outcome or question, the repository or system
in scope, and any consequence that matters. For example:

> “The cache replacement is clear and local. Please make the smallest change,
> run the relevant checks, and tell me what remains.”

or:

> “I do not know whether this authorization boundary is correct. Help me find
> the important unknowns before we change code.”

The agent first works out whether the request is clear Direct Work, a bounded
supporting question, or a human-owned choice. It recommends one proportionate
next move when a forward choice is needed. You do not need to name a Praxis
capability.

## What happens next

1. The agent states the current question and the evidence it needs.
2. It works autonomously inside the active question and current authority.
3. It pauses for a human-owned choice, approval, acceptance, or exact effect
   authority when that boundary is reached.
4. It returns the result, decisive evidence, limitations, and learning.
5. It stops instead of preparing the next piece of work by momentum.

Read [Working with Praxis](working-with-praxis.md) for the observable control
rules, or start with the [premise](../concepts/premise.md) and [system
model](../concepts/system.md) when you need the durable explanation.

## Explicit repository Setup

Ask for Setup only when you want repository-local Praxis readiness, Plannotator
readiness, a named integration, repair, removal, or Docker preparation for a
selected Security audit. Setup inspects existing state, preserves intentional
configuration, and makes only the requested change. It does not create empty
Projects, wrappers, services, or a global Praxis state directory.

Plannotator is required only for interactions that select its native review or
gate surface. A simple standalone result can be accepted in conversation.
Docker is optional and is recommended only by a selected Security audit when
disposable isolation would materially improve the evidence. A Setup choice
prepares readiness; it does not authorize a later audit or probe.

## Availability boundary

The catalog describes the accepted capability boundaries, and all 28 runtime
package directories are included in the 1.0.0 plugin. Check the current tree
and [changelog](../../CHANGELOG.md) before relying on a package or integration.
