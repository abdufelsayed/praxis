# Examples

These are short contrasts for orientation, not executable tests, golden
transcripts, or a mandatory ceremony. The same ordinary-language request can
take a different path when its uncertainty, consequence, or continuity
changes.

## Direct Work

> “Rename this local function to match the existing convention, update the
> affected test, run the focused checks, and report the diff.”

The behavior and local pattern are clear, and the mutation is ordinary and
reversible. The agent edits, verifies the material claim, reports evidence and
limits, and stops. It does not manufacture a Project, Plan, Commit, or review
gate.

## Bounded Delivery

> “The approved Issue describes session revocation. Let’s plan one bounded
> implementation and then implement it.”

Delivery develops one Implementation Plan and stops at Plan Approval. A later
explicit Implementation Authorization releases only that Plan’s ordinary
mutations. Delivery implements, reviews, verifies, returns learning, presents
the appropriate result judgment, and stops. Commit, push, deployment, and the
next Plan remain separate choices.

## Evolve

> “This Project has two genuinely useful working forms: first a readable
> import preview, then a committed import. Help us compare that progression.”

Formalization recommends Evolve and the human chooses it. Evolve develops an
Evolution Map with at least two coherent advances, passes Map Approval, and
waits for the human to select one Evolution. It does not invent detailed
Issues or later Plans before their turn.

## Pair

> “Pair with me while we implement the next approved Plan, one decision-sized
> mutation at a time.”

The direct request enters Pair during Delivery. The human and agent keep one
driver and one explicit permission boundary. Each mutation remains temporary,
scoped, and revocable; a stop or redirection pauses at the earliest safe point.
Pair returns the integrated result to Delivery and never grants broad
authority.

## Orient: suggested and declined

The agent may say:

> “A short explanation of this settled ownership model would make the next
> review easier. Would you like that orientation?”

If the human agrees, Orient teaches one bounded model, checks comprehension,
and returns uncertainty to the caller. If the human declines, the caller keeps
working with a concise ordinary explanation. Neither choice changes the route,
approval, mutation authority, or acceptance boundary.

## A safety return

> “Delete the old production data after the migration.”

This is consequential. The work needs an approved Plan and exact
Implementation Authorization before Check Safety can preflight the action. If
either boundary is missing, the caller returns `revise` with the missing
boundary instead of performing a ceremonial preflight or mutating data.
