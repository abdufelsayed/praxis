# Working with Praxis

Praxis is a network of small owning loops, not a lifecycle that every request
must traverse. The agent navigates the current question; the human retains
meaning, forward choices, acceptance, and effect authority.

## The visible control loop

For a bounded request, expect this sequence:

1. **Recommendation.** The agent explains one proportionate path and why it
   fits the current evidence.
2. **Human choice.** A forward owner, route, supporting orientation, or
   explicitly invoked workflow begins only when its entry rule is satisfied.
3. **Bounded work.** The active owner investigates, proposes, implements, or
   verifies without asking for routine permission inside its boundary.
4. **Authority at the effect.** Mutation or an external action waits for the
   exact human action, target, and effect when the current request does not
   already contain it. Approval never supplies that authority.
5. **Evidence return.** The owner reports what happened, what it means, what
   remains valid, limitations, unresolved questions, and the causal owner of
   any changed truth.
6. **Stop.** Acceptance, exhaustion, refusal, invalidated truth, or a safe
   blocker returns control to the human. Adjacent work is not implied.

When the current message already selects an owner and satisfies its entry,
recommendation and human choice are already resolved: Using Praxis transfers
the minimum context and exits, and that owner begins its bounded work. The
navigator does not perform the owner's work or remain active above it.

Recommendations are navigation, not permission requests. A supporting skill
answers the bounded question its caller gives it and returns; it does not take
the caller’s gate, route, authority, or stopping rule. Once a supporting
condition is present, the active owner invokes it without asking the human to
remember an internal skill, consumes its bounded return, and only then
completes that step.

## Choosing a proportionate path

Clear, reversible work can stay Direct Work or enter bounded Delivery without
a Plan when target, exclusions, risk, authority, and proof are already settled.
A Plan is useful when the approach, recovery, integration, or proof deserves
judgment before implementation.
Issues, Projects, Evolutions, and Initiatives exist only when their distinct
meaning improves judgment or continuity. Evolve requires at least two
independently meaningful working forms; size alone never creates it.

The human chooses a forward route in ordinary language. Approval of a
Requirements bundle, Evolution Map, Issue, or Plan accepts only that named
proposal. Plan Approval is followed by a separate Implementation Authorization,
even when both acts appear in one message.

## Supporting capabilities

Research, Interview, Make Tangible, Review, Verify, Security, Delegate, and
other capabilities are bounded calls. Their returns remain evidence or a
scoped result for the owner. Orient is a human-selected teaching interaction;
Pair is a human-initiated collaborative implementation posture and is never
inferred or recommended. Plannotator presents a selected native interaction,
but its approval is not implementation authority.

## Redirection and learning

When evidence changes accepted meaning, revise the narrowest causal owner and
repeat only the affected gate before sending corrected truth forward. Local
correction is valid while accepted meaning, targets, exclusions, consequences,
proof, and authority remain intact. If they do not, stop affected mutation,
make the current state safe, return partial evidence, and wait for a new human
choice.

Feedback types remain distinct: preference is not proof, critique is not
acceptance, and a passing check is not authority. Preserve only learning a
future owner needs; source, tests, Git, and artifacts remain the evidence for
reconstructible implementation truth.

## Resumption and context

On resumption, reconstruct the current question from the latest human
direction, relevant accepted records, current source/tests/Git, and any
temporary Delivery checkpoint that is genuinely needed. Load context
progressively. The presence of a file does not prove that an Evolution was
selected, a Plan was authorized, or a result was accepted.

context](../concepts/context.md), and [work and routes](../concepts/work.md).
