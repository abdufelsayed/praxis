# Delegate

Delegation is a context boundary, not an ownership transfer. The supervising
agent keeps human context, scope, authority, integration, and the final claim.

## Prove the benefit

Delegate only when the benefit survives briefing, correction, integration, and
review cost: protecting the main context from noisy work, using a cheaper capable
role, obtaining genuinely independent evidence, or reducing elapsed time through
independent work. Keep small targeted changes and work needing frequent human
exchange in the current context.

Write a clean brief containing the bounded outcome, accepted truth, scope and
exclusions, authoritative starting pointers, mutation authority, required proof,
return format, escalation conditions, and stop conditions. Pass the minimum useful
context, not the transcript or a preferred conclusion.

Inspect overlapping files and shared resources. Use one mutating owner where
checkouts, generated state, databases, services, ports, credentials, or remote
resources overlap. A worktree isolates files, not those resources.

## Choose the role

Read [role guidance](references/roles.md) when the choice is not obvious.

- **Scout:** trace local behavior and ownership.
- **Researcher:** answer a bounded external or domain question.
- **Worker:** implement one understood boundary.
- **Reviewer:** challenge one fixed target.
- **Verifier:** test exact claims.
- **Oracle:** give independent judgment on consequential direction or disagreement.

Use a fresh isolated context and the cheapest capable role. Only a Worker may
mutate product state, and only within the user's authorized implementation
boundary. Other roles are read-only except for explicitly authorized disposable
verification artifacts.

Supervise by exception: blockers, scope conflict, changed truth, safety or
authority concerns, or evidence that should stop related work. Resume the same
delegate for a local correction while its brief remains valid; issue a new brief
when the problem materially changes.

Inspect the returned target, evidence, changes, proof, limits, and deviations
before integrating it. Preserve disagreement instead of vote-counting. Delegation
never authorizes commit, publication, deployment, or continuation.
