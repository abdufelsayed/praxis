# Artifacts and questionnaires

Use this method when the requester wants to react to an artifact, compare a few
alternatives, review the latest response, or answer a small questionnaire.

## Preserve the real question

Name what the requester is judging before opening Plannotator. Present the
smallest complete surface that preserves that judgment: a Markdown file,
self-contained HTML page, stable URL or capture, bounded folder, or the latest
response can all work.

Use the artifact's native medium when Plannotator would hide essential behavior
from a live application, terminal, video, audio, device, or latency-sensitive
interaction. Do not rebuild an artifact merely to make it reviewable here.

For comparisons, keep consequential fidelity comparable and disclose meaningful
differences in polish, realism, interactivity, and completeness. Preserve mixed
or uncertain reactions instead of forcing a winner.

## Use a questionnaire sparingly

A questionnaire is useful for a small set of independent, already-grounded
questions that are easier to answer together. Keep dependent discovery in
conversation, where each answer can change the next question.

The calling skill owns the questions and any recommendation. Plannotator only
presents them and returns answers. Preserve skipped questions, custom answers,
notes, uncertainty, and requests for more context.

Inspect current help to select the supported artifact, comparison,
latest-response, or questionnaire command. Do not rely on a cached payload shape.
Temporary transport files stay outside `.praxis/<effort>/` and can be discarded
once the interaction no longer needs recovery.

## Return the reaction

Return the exact target or version, annotations, choices, feedback, fidelity
limits, and unresolved points. The calling skill decides whether meaning changed,
whether another review is useful, and whether anything should be persisted.
