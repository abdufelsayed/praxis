# Explicit approval

Use this method only when the requester asks to approve one substantial plan or
result.

Name the complete target, exact revision, approval claim, and what approval would
not authorize. Present the complete current target; use a diff only when its
baseline is known and reliable. Inspect current Plannotator help for the supported
approval interaction instead of relying on cached flags.

Interpret the response narrowly:

- approval accepts only the presented revision and claim;
- feedback without approval requests reconsideration;
- dismissal or empty closure supplies no judgment; and
- transport failure leaves the requested review unfinished.

Meaning-changing feedback returns to the skill that owns the plan or result. If
explicit approval is still wanted after a material revision, present the new
revision. Approval does not authorize implementation, commit, push, publication,
deployment, merge, or unrelated follow-on work.
