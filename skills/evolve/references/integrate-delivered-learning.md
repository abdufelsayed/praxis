# Integrate Delivered Learning

Load this method only when an integrated delivered result returns for Evolution
Acceptance or changes future progression.

Before asking for acceptance, identify the actual working result, proved
coverage and evidence scope, unproved claims, checks and limits, remaining
uncertainty, exact acceptance claim, and excluded adjacent actions. A partial
result must remain visibly partial.

Keep working-form proof separate from learning-target evidence. When the requester
selected durable tracking, record only proved coverage, decisive evidence
pointers, remaining limitations, and causal learning on the Evolution.

Classify learning before editing progression:

- changed needs, constraints, or Project boundary return to Requirements
  Discovery;
- changed high-level Evolution meaning returns to its owning definition;
- detailed behavioral gaps return to Issues; and
- only evidence changing the number, order, boundary, meaning, or progression
  of future Evolutions revises the Map.

A material Map revision foregrounds its semantic difference and preserves
unaffected accepted Evolutions. Present the changed frontier before recommending
the next choice. Acceptance of one result never selects or starts the next
Evolution.
