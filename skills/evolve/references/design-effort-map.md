# Design an Effort Map

Load this method when creating or materially revising an effort map.

Start from one accepted destination and current position. Design the smallest
serious sequence of integrated working advances. An advance is tangible enough
to exercise, review, prove, and learn from; a feature category, technical layer,
milestone, release, or learning activity alone is not an advance.

The map contains only:

- the observable destination and current position;
- decisions so far, preferably as pointers to their owners;
- the decision frontier and real blocking edges;
- fog deliberately left until earlier learning; and
- explicit exclusions.

A question belongs on the frontier when it can be stated precisely now. Keep it
in fog when earlier learning can still change what the question is. Research,
Interview, Make Tangible, and Design Solution own their respective questions;
the map owns only navigation and useful sequence.

Give persisted advances stable descriptive names and state their tangible
advancement, deliberate limitations, why their position is useful, and a learning
target only when it can change a named later judgment. Keep future advances high
level. Define Issues and Plan own implementation detail.

When several sequences are serious, compare their consequences and recommend
one. When one coherent tracer bullet reaches the destination, recommend Define
Issues instead of manufacturing a map. When every sequence is artificial because
the destination or requirements are wrong, return that changed meaning to
Discover Requirements.

Persist the map only for a named future consumer. It remains an index: decisions,
specifications, issues, and evidence stay with their owners.
