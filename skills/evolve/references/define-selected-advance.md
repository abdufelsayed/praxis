# Define the Selected Advance

Load this method only after the requester selects one working advance from the
current effort map.

Resolve the selection by its stable descriptive name and current meaning. If it
is missing, ambiguous, stale, or identified only by sequence position, return the
exact repair needed rather than defining a different advance.

Define one complete high-level working form with only the material it needs:

- governing accepted meaning;
- tangible advancement;
- included high-level behavior;
- integration with existing work;
- deliberate limitations;
- learning target, when it changes a named later judgment;
- required proof; and
- open decisions.

Stay above detailed interfaces, edge cases, acceptance criteria, files, commands,
implementation sequence, and checks; Define Issues and Plan own those. Anything
necessary for the promised advancement remains included for later issue
definition.

Keep the definition in conversation unless the effort needs cross-session
continuity. Recording an advance does not mean it was delivered or accepted.
