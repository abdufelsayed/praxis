# Spec

Describe what should be true.

## Include

- Goal and non-goals.
- Users or callers.
- Required behavior.
- Constraints.
- Acceptance criteria.
- Risks and unknowns.

## Avoid

- implementation task lists;
- discarded conversation branches;
- vague "handle edge cases" language;
- requirements the user has not agreed to.

After the spec is clear, use `praxis:plan`.
