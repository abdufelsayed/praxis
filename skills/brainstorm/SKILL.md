# Brainstorm

Turn fuzzy intent into a direction the user recognizes.

## Inputs

- User idea, product/workflow sketch, rough UI request, or architectural direction.
- Known audience, constraints, repo facts, and preferences.

## Flow

1. Understand purpose, audience, constraints, and success criteria.
2. Inspect enough context to avoid generic advice.
3. Ask one focused question when the answer changes the direction.
4. Offer 2-3 viable approaches with tradeoffs.
5. Recommend one approach and explain why.
6. Identify the smallest artifact or next action that would make the direction executable.

Keep brainstorming lightweight for small work. Do not force a full design ceremony for tiny reversible tasks.

## Output

- clarified goal;
- options and tradeoffs;
- recommended direction;
- open questions;
- next skill: `spec`, `decide`, `plan`, `explore`, or stop.
