# Brainstorm

Turn fuzzy intent into a direction the user recognizes.

## Flow

1. Understand purpose, audience, constraints, and success criteria.
2. Ask one focused question at a time when needed.
3. Offer 2-3 viable approaches with tradeoffs.
4. Recommend one approach and explain why.
5. When approved, load `praxis:spec` or `praxis:plan`.

Keep brainstorming lightweight for small work. Do not force a full design ceremony for tiny reversible tasks.

## Next Skills

Load `praxis:distill` before preserving brainstorming output as exploration, decision, spec, or plan material. Load `praxis:spec` when requirements need to be captured before planning.
