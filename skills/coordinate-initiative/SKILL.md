# Coordinate Initiative

Load [Praxis Control](../../references/control.md) and
[Product Discovery Collaboration](../../references/collaboration.md).

Use this capability only when the requester directly asks to understand or
accept shared meaning across two or more independent Projects, or accepts a
bounded cross-Project coordination suggestion. Work in `understand` and
`accept_meaning`. A lone Project or already-sufficient
relationship is `no-op`. Coordinate Initiative owns shared
meaning, relationships, ordering rationale, alignment, closure, and stopping;
Project-local truth stays with each Project.

## Establish shared meaning

Bind the strategic objective, success conditions, participating Projects and
owners, shared constraints and accepted truth, relationships and dependencies,
ordering rationale, evidence, uncertainty, and current Initiative revision.
Do not flatten Project Outcomes, Requirements, Issues, Plans, or authority into
an Initiative backlog.

For each Project state what it contributes, needs from others, exposes, and
owns independently. Distinguish a hard dependency from useful sequencing and
mere coordination convenience. Ordering should be justified by shared value,
learning, risk, compatibility, or dependency; it does not start Project work.

Use [Research](../research/SKILL.md) for a bounded shared fact,
[Interview](../interview/SKILL.md) for a human strategic judgment,
[Orient](../orient/SKILL.md) for an accepted teaching interaction,
[Make Tangible](../make-tangible/SKILL.md) for a relationship or sequencing
surface, and [Design Solution](../design-solution/SKILL.md) for a consequential
cross-Project shape. Preserve and consume each exact result:

- Interview keeps `clarified`, `qualified`, `deferred`, `conflicting`,
  `no-op`, `needs-evidence`, `blocked`, and `stopped` distinct.
- Research retains `answered` as scoped evidence and presents any strategic
  consequence for human judgment before it changes shared meaning; keeps
  `unverified` or `conflicting` scoped; treats `no-op` only as sufficient
  existing context; and preserves `needs-human-judgment`, `blocked`, or
  `stopped`.
- Orient begins only after accepted human agreement. Preserve `explained`,
  `understanding-observed`, `understanding-unconfirmed`,
  `misconception-unresolved`, `orientation-blocked`, `causal-return`, and
  `stopped`; comprehension is not alignment.
- Make Tangible preserves `no-op`, `constructed`, `revised`, `blocked`, or
  `stopped` with artifact, reaction, fidelity, and retention limits.
- Design Solution preserves `recommended`, `selected`, `qualified`,
  `no-choice`, `revised`, `refused`, or `stopped`; none is Initiative meaning
  by itself. Integrate only the consequence the requester selects or qualifies.

Changed Project-local truth returns to its Project owner; changed shared truth
remains here. No dependency passes Alignment, grants authority, or chooses a
Project route.

If common strategic judgment disappears—because Projects no longer share a
meaningful objective, relationship, or decision—recommend a split and preserve
the useful Project boundaries. Do not maintain an Initiative for reporting
convenience alone.

## Persist and gate only shared navigation

Persist an Initiative only when shared navigation must survive across Projects
or sessions. Load [record foundations](../../references/records/foundations.md)
and [discovery records](../../references/records/discovery.md). Keep the
Initiative Brief limited to objective, success, participating Projects,
relationships, shared constraints, ordering rationale, uncertainty, accepted
revision, and links. A Project may live beneath one Initiative or remain
standalone; another Initiative may reference it without jointly owning it.
Never duplicate Project specifications or plans.

Present the complete stable Initiative Brief through a
[Plannotator](../plannotator/SKILL.md) Record Gate when Initiative Alignment is
needed. Approval accepts only that revision. Semantic feedback revises and
re-gates affected shared meaning. Denial or dismissal stops; transport failure
blocks without conversational approval.

Preserve native `approved` and `annotated` decisions, plaintext feedback,
denial, dismissal, closure, transport failure, and references exactly. Only an
explicit `approved` decision passes the named Alignment or Closure judgment.

Closure judges one named strategic objective as satisfied, rejected, or
superseded from current Project evidence. It does not imply every Project is
complete. Use a Result Gate for durable composed closure, preserve the exact
disposition and replacement when superseded, and leave Project Briefs with
their owners.

Return `coordinated`, `aligned`, `revised`, `split-recommended`, `closed`,
`needs-human-judgment`, `blocked`, `stopped`, or `no-op` with Projects and
relationships, shared truth, ordering, evidence and limits, gate decision and
feedback when used, causal owner, and next strategic judgment. Do not start or
edit Project-local work, implement, commit, publish, or deploy.
