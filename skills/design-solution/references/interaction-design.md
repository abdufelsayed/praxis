# Interaction design

Use this lens when candidate solutions differ in actor sequence, states,
feedback, handoffs, interruption, failure, or recovery. It applies to user
interfaces, commands, operations, approvals, background work, and
human-agent interaction. Keep interaction reasoning tied to the same bounded
choice.

## Reconstruct the work

Identify each actor, goal, authority, entry condition, observable state, and
point at which the intended outcome is complete. Trace current behavior when
it matters; a written happy path is weak evidence about interruption or
recovery. Distinguish feedback an actor can actually observe from hidden work.

## Compare complete journeys

For every serious candidate, walk the ordinary path and feedback, then waiting,
cancellation, interruption, resumption, invalid input, unavailable
dependencies, partial completion, handoff, and recovery. Record whether
progress and the next action remain legible. Include accepted accessibility,
latency, and cognitive constraints when they can change the judgment.

Flag a workflow that hides consequential work behind success-looking feedback
or makes an actor responsible for information they cannot possess, and return
that evidence to Design Solution for shared comparison and elimination.
Identify when a diagram, simulation, or prototype is needed to expose a
material difference prose cannot expose cheaply. Return the exact judgment and
fidelity need to Design Solution; this reference does not construct or present
the surface or select a candidate.

Return the candidate journeys, responsibilities, states, feedback, failure and
recovery consequences, evidence, unresolved uncertainty, and earliest owner
affected.
