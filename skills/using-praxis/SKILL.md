# Using Praxis

Route one concrete request to ordinary direct work or the smallest Praxis method
that resolves its present uncertainty. Praxis is optional, recursive, and
human-led. It is not a pipeline that every change must traverse.

## Reconstruct the current question

State what the requester needs next, what is already accepted, what remains
uncertain, the current evidence, and the authorized effect boundary. Inspect
existing `.praxis` material only when it changes that answer. A clear contained
task stays direct; the presence of Praxis files does not create ceremony.

## Choose the causal owner

Use the question being answered, not a presumed lifecycle position:

- unclear needs, constraints, outcomes, or boundaries -> **Discover
  Requirements**;
- human-owned intent, preference, priority, tolerance, or meaning ->
  **Interview**;
- a bounded factual premise -> **Research**;
- a perceptible question that needs something to see, compare, or manipulate ->
  **Make Tangible**;
- one consequential technical shape -> **Design Solution**;
- accepted meaning that needs a durable reader-ready specification ->
  **Write Spec**;
- a foggy destination too large for one implementation context -> **Evolve**;
- an accepted outcome that needs vertical tracer bullets -> **Define Issues**;
- one selected issue that needs an implementation contract -> **Plan**;
- one authorized working result -> **Deliver**;
- unexpected behavior with an unknown cause -> **Debug**;
- demonstrated structural pressure -> **Refactor**;
- a checkout collision, rollback need, or isolated experiment -> **Manage
  Worktree**;
- one settled model the requester needs to understand -> **Orient**;
- a fixed target that needs challenge or proof -> **Review**, **Verify**, or
  **Security** according to the question.

The requester may directly choose **Pair**, **Delegate**, or **Plannotator** when
they want those collaboration surfaces. **Commit** and
**Prepare PR** apply only when requested. **Setup Praxis** applies only to
installation or repository configuration.

Skip every settled question. If new evidence changes earlier meaning, return to
the earliest skill that owns that meaning instead of correcting downstream
documents or preserving later work by workaround. After that question is
resolved, route again from the new truth; never restart the whole map by habit.

## Recommend one next move

Give one recommendation in the project's language: what is understood, which
method fits, what uncertainty it resolves, and what can be skipped. A
recommendation does not invoke a user-only skill, authorize mutation, approve a
result, or start the following activity.

Keep ordinary work in conversation. Persist under `.praxis` only when the
requester asks or a named future consumer needs an effort to survive this
conversation. Stop after the route is clear.
