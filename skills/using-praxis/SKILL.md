# Using Praxis

Praxis is a toolbox with a light lifecycle, not a mandatory control layer. Read
the current request, source, tests, Git state, and only the nearest relevant
`.praxis` material. Current human direction overrides stale records.

Keep skill selection internal unless the requester asks how to proceed. Route by
the actual uncertainty:

- unknown needs, constraints, or boundaries → Discover Requirements;
- a human-owned decision tree → Interview;
- a factual question → Research;
- a perceptible design question → Make Tangible;
- one consequential architecture choice → Design Solution;
- accepted meaning needing a specification → Formalize;
- a huge uncertain destination → Evolve;
- a settled outcome needing tracer-bullet work → Define Issues;
- a selected issue needing implementation choices → Plan;
- authorized implementation → Deliver, or Pair when explicitly requested;
- an unknown failure cause → Debug;
- demonstrated structural pressure → Refactor;
- an exact completion claim → Verify;
- a fixed target needing adversarial inspection → Review;
- a credible attacker path → Security;
- shared meaning across independent projects → Coordinate Initiative.

Contained work with clear meaning, target, authority, and proof remains direct
work. Supporting skills can be used at the seam that needs them; they do not form
a compulsory sequence.

Persist under `.praxis` only when the requester asks or a named future consumer
needs cross-session continuity. Documentation updates, Plannotator review,
delegation, worktrees, commits, PRs, publication, and external actions occur only
when requested or when the authorized task specifically requires that bounded
operation.

When the route is still consequentially ambiguous, recommend one next skill in
project language, explain what it resolves, and wait. Otherwise load the selected
skill and continue in the same turn.
