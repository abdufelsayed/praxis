# Using Praxis

Load [Praxis Control](../../references/control.md). Act as the thin host-facing
adapter for one concrete request. Establish or reconstruct its active inquiry,
load the smallest useful capability, transfer clean context, and exit. Perform
no capability work here.

## Establish the inquiry

Enter when the requester invokes Praxis, asks to resume Praxis-owned work, asks
about Praxis itself, or existing Praxis truth makes the live inquiry genuinely
unclear. Bind the concrete question, current lifecycle position, judgment owner,
posture, accepted and provisional context, unresolved conditions, close
condition, effect policy, persistence policy, and authority references.

A direct `$skill` invocation already selected a capability and bypasses this
adapter, but that capability still reconstructs enough inquiry context to obey
shared control. A clear contained request remains Direct Work when Praxis was
not invoked and no Praxis truth changes its meaning.

## Reconstruct only inquiry-relevant truth

Start with current human direction, source, tests, Git state, interfaces, and
observable behavior. When durable Praxis state must be located or resumed,
load [Record Navigation](references/record-navigation.md) and read only the
nearest governing records, necessary ancestors, decisive evidence, and current
position.

Distinguish accepted truth from drafts, recommendations, results, limitations,
stops, and pending judgments. Reconstruct the live question, position, accepted
and provisional context, latest result and proof, limitations, effect and
persistence policy, authority references, close condition, and exact judgment
still required. If evidence changed the question, reframe the same inquiry and
state what changed and remained valid. Follow Praxis Control's causal-return
pointer when the earliest meaning owner or affected authority is unclear.

Keep capability selection internal unless it changes a meaningful transition.
Talk about the concrete product question and next judgment, not the skill
taxonomy. A direction to discuss, pause, not start, or not edit narrows the
inquiry immediately and cannot become tool use, persistence, delegation, a
gate, or another effect unless it explicitly requests a bounded read-only check.

## Load the smallest useful capability

Choose by the live inquiry rather than by a fixed workflow sequence:

- unresolved needs, outcomes, constraints, feasibility, or boundaries →
  [Discover Requirements](../discover-requirements/SKILL.md);
- accepted meaning needing a coherent working-form or specification shape →
  [Formalize](../formalize/SKILL.md), which may compose
  [Evolve](../evolve/SKILL.md) or
  [Define Issues](../define-issues/SKILL.md) after the requester selects the
  concrete product transition;
- a selected progressive sequence of meaningful working forms →
  [Evolve](../evolve/SKILL.md);
- a selected outcome needing complete observable behavior and proof →
  [Define Issues](../define-issues/SKILL.md);
- a selected result needing a judgeable implementation proposal →
  [Plan](../plan/SKILL.md);
- authorized work needing implementation, assurance, or Result Acceptance →
  [Deliver](../deliver/SKILL.md);
- shared meaning across independent Projects →
  [Coordinate Initiative](../coordinate-initiative/SKILL.md);
- contained reversible work whose meaning, target, effect, authority, and proof
  are already clear → **Direct Work**.

Inside an established inquiry, its active lifecycle capability autonomously
loads bounded supporting capabilities such as Research, Interview, Make
Tangible, Design Solution, Review, Verify, Security, Delegate, Debug, Refactor,
or TDD. Effect and repository capabilities retain their explicit local entry.
Do not route the requester through those names merely because the active
capability uses them.

## Transfer clean context and exit

When current direction already selects or resumes the concrete work, load the
capability's `SKILL.md`, pass the compact Inquiry envelope and exact governing
record, evidence, authority, and return references it needs, and begin it in
the same turn. The capability chooses its conditional references and bounded
supporting calls.

When a meaningful lifecycle transition is still required, return one
`transition-recommendation` in the Project's language with the current
position, convergence basis, recommended next working form, reason, newly
allowed work, still-unauthorized work, and real alternatives, then wait. For
Direct Work, return `direct-work` to ordinary behavior within authority already
present. A same-turn capability handoff is `transferred`; insufficient context
is `blocked`; a human stop is `stopped`. After one return, stop adapting.
