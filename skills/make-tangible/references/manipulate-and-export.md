# Manipulate and Export

Load only when structured values must be tuned, classified, arranged, or
edited and an explicit proposed result is needed. The surface does not apply
the change or inherit authority over the underlying system.

## Keep the editor bounded

Start from inspectable source identity and scope. Expose only fields,
operations, context, and constraints needed for one judgment; leave unrelated
state read-only or absent. Keep loaded source, current scope, proposed state,
and unchanged state visibly distinct. Validate identities, required fields,
allowed combinations, dependencies, ordering/cardinality, and caller-supplied
limits. Block genuinely invalid results, but show warnings and qualified
results. Suggestions never silently repair, reorder, default, or expand a
consequential edit.

## Export a safe proposal

Export the source version, proposed diff (and complete value only when needed),
stable identities/order, qualifications, unresolved values, warnings, and
artifact version. Label it proposed state; export or patch does not grant
implementation, production, or external authority. Bind the edit to the loaded
source and detect stale baseline before final export. Inspect current state,
rebase without guessing where possible, show semantic changes, and reopen only
reactions whose meaning changed. Never overwrite newer state.

Elicitation, comparison, exploration, inspection, observation, or proof may
support the editor when they clarify the proposed change; this pattern remains
primary while reliable structured manipulation and export are the judgment.

Verify source/scope, edits, identities, validation, warnings, reset/undo,
stale-baseline handling, export fields, and practical round-trip. Return exact
version, source identity, diff/value, qualifications, validation, stale
reconciliation, conflicts, and implication. The caller decides whether to
promote or later apply it under separate authority.
