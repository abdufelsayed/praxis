# Setup

Inspect first and change only the requested setup surface.

## Establish the requested minimum

Bind the repository, requested capability, exact target, and whether the request
covers plugin installation, repository-local `.praxis` state, Plannotator,
another named integration, or removal. Inspect repository instructions, Git state,
ignore rules, tracked and untracked state, existing agent configuration, current
tool help, and native integrations. Preserve tracked content and unrelated
configuration.

For project-local state, add a root `/.praxis/` ignore entry only when the
request covers local Praxis artifacts and it is genuinely missing. Do not create
empty record trees, templates, wrappers, hooks, services, or accounts.

Install or repair a tool through a current official method established from the
environment or authoritative documentation. Verify capability through the exact
commands and structured options the workflows need, not a version string alone.
Leave optional integrations alone unless named.

Migrate legacy records only when explicitly requested. Inventory every source and
destination, preserve stable identity and links, and block on conflicting
destinations, ambiguous ownership, tracked-state risk, or unsafe rewriting.

Before a state change, state or resolve its command, target, network, privilege,
credential, cost, persistence, and recovery. Use Check Safety for a consequential
installation, permission, secret, remote, or cleanup effect.

## Verify idempotence

Reinspect repository and tool state after each change. Confirm the requested
condition, command surface, ignore behavior, integration configuration, and
limits. A second run should preserve correct state without duplicate entries,
overwrites, placeholders, or environment drift.

Report what changed or was already correct, decisive checks, unavailable or
intentionally unconfigured surfaces, and one useful next step. Setup grants no
authority to use the capability or begin another workflow.
