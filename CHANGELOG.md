# Changelog

This file records public behavior and compatibility changes.

## Unreleased

- Requires ASD-STE100 Simplified Technical English in all communication.
- Adds a research-to-judgment transition brief, provisional topic map, and
  explicit requester selection before product interviewing begins.
- Defines delivery boundary statements, meaningful checkpoint updates,
  temporary recovery checkpoints, honest partial returns, and post-acceptance
  record projection under the shared record-ownership rule.
- Replaces adjacent-step backtracking with selective recursive reconciliation:
  evidence opens a challenge, an impact map exposes affected descendants, and
  accepted changes propagate only through dependent meaning and authority.
- Adds executable contract coverage for record anatomy, communication,
  delivery, open challenges, and learning impact maps.
- Makes one transient, revisioned Inquiry the unit of work, with non-linear
  `understand`, `accept_meaning`, `shape`, `deliver`, and `learn_return`
  positions and requester-controlled meaningful transitions.
- Reclassifies skills as lifecycle, supporting, interaction/effect, or
  repository capabilities so supporting work can run autonomously without
  taking route, gate, authority, or continuation control.
- Adds a host-neutral, stateless Proposed Action contract with fixtures for
  revision, gate, authority, direction, persistence, and selective-staleness
  decisions; no installed host interceptor is claimed.
- Makes persistence record-kind-specific and automatically preserves
  substantial research talking points, observations, inferences, learnings,
  contradictions, limits, provisional implications, and named consumer
  without promoting them to accepted product truth.
- Binds durable gates and authority to exact record revisions and separates
  meaning, gate, disposition, and authority state, including selective
  invalidation and withdrawn authority.

## 1.1.0 - 2026-08-09

- Adds paired product-discovery guidance for concrete question framing,
  package-versus-application ownership, dependent conversational questions,
  independent Plannotator bundles, coherent persistence, and immediate
  pause/correction handling.
- Adds canonical Research Findings records and an explicit
  evidence-to-interpretation-to-interview harvesting checkpoint before
  promotion into atomic Requirements.
- Requires each additional record type to have a distinct purpose, consumer,
  lifecycle, and authority boundary.
- Strengthens clean delegation briefs so independent agents receive neutral
  bounded questions and exact pointers rather than conversation transcripts
  or preferred conclusions.
- Clarifies that pseudo-APIs are provisional decision aids, required gates
  remain native Plannotator gates, and Formalization cannot consume raw
  research as an accepted Requirements baseline.
- Applies the paired-collaboration and evidence-harvest contract to progressive
  working forms, detailed specification, and Initiative strategy; keeps route
  taxonomy internal; and continues dependent questions within one inquiry.
- Makes Map, Evolution Definition, Issue, Result, and Evolution Acceptance
  gates consistently native while selecting Review and Verify from actual
  assurance needs instead of composing both by ritual.

## 1.0.0 - 2026-08-05

Praxis 1.0.0 is the assembled 28-package Codex plugin. It includes the
plugin-local concept owners, maintainer specifications, runtime references,
host metadata, integration boundaries, and reconciled authority, dependency,
safety, Pair, and routing contracts.

- Includes an Agent Plugins v1 portable core manifest while retaining the
  separate Codex-native adapter and stating the combined-tree portability
  boundary.
- Makes Using Praxis the only implicitly selectable Codex owner; leaf owners
  remain explicitly callable and internally reachable by active owners.
- Provides the shared owner-control contract, compact runtime projections,
  owner-local conditional methods, and reconciled dependency returns.
- Allows clear reversible Delivery through a directly authorized
  implementation boundary while retaining Plans whenever a proposal needs
  judgment.
- Uses `.praxis/` for canonical durable records, reads released
  `.agents/{initiatives,projects,issues,plans}` records for compatibility, and
  provides an explicit conflict-checked Setup migration path.
- Strengthens Evolve Map identity, selection, one-advance routing,
  proportional gates, delivered-learning integration, and terminal stopping.
- Keeps specifications and human documentation outside agent runtime and
  checks the portable manifest and invocation policy in repository validation.
- Codex installation is provided through the repository-local
  `praxis-personal` marketplace.
- Pi and OpenCode remain separately managed native hosts; their dotfiles
  entrypoints synchronize their own configuration and skill surfaces rather
  than sharing Codex's marketplace cache.
- Plannotator remains conditional outside formal judgments; every named Record,
  Result, and Code Review gate uses its native interaction.
- The design snapshot is comparison material and is not a runtime dependency.
